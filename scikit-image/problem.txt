=== Background ===
Scikit-image is a high-performance image processing project, part of the larger scikit
project. This particular module is implemented in pure python. You are going to implement a
fix to the skimage.feature.peak_local_max function.

The min_distance parameter is meant to guarantee that any two peaks returned from a single
call are always at least min_distance pixels apart. Concretely: for any two coordinates the
function returns, the largest absolute difference taken over the individual axes must be at
least min_distance. (This is the Chebyshev / L-infinity distance).

=== The problem ===
This guarantee is not always upheld. The following script reproduces a violation:

```
import numpy as np
from skimage.feature import peak_local_max

image = np.zeros((30, 60))
image[15, 20:41] = 5.0  # a region of pixels all at the image's maximum value

coords = peak_local_max(image, min_distance=10)
print(len(coords))  # currently 21 -- many of the returned coordinates are only 1 pixel apart,
                     # far closer than min_distance=10
```

For contrast, the following input already behaves correctly, and should do so after your fix:

```
image = np.zeros((30, 60))
image[15, 30] = 5.0
image[15, 32] = 3.0
coords = peak_local_max(image, min_distance=10)   # correctly returns only [[15, 30]]
```

Peak detection is additionally unreliable when the `labels` argument is used. As one
symptom, the call modifies the caller's own input array:

```
img = np.zeros((10, 20))
img[3, 3] = 4.0
img[5, 15] = 4.0
labels = np.zeros((10, 20), int)
labels[2:5, 2:5] = 2       # label values are arbitrary positive integers;
labels[4:7, 13:17] = 5     # here they are 2 and 5, not necessarily consecutive or 1-based
before = labels.copy()

peak_local_max(img, labels=labels, min_distance=1)
print(np.array_equal(labels, before))   # currently False: the input `labels` array was
                                         # modified in place as a side effect of the call
```

=== Your task ===
Fix peak_local_max so that no two coordinates it returns are ever closer than min_distance
apart, measured by the metric defined above (the maximum per-axis absolute difference).

Precise requirements the solution must satisfy:
- When `labels` is not used, no two returned coordinates may be closer than min_distance apart
  by the metric above. This must hold for every case, not only the cases that already work
  today. (For the labeled case, see the `labels` requirement below.)
- The fix must not achieve spacing by discarding legitimate results. Every region of the image
  that contains one or more qualifying maxima must still contribute at least one
  coordinate to the output and must never be dropped entirely. When several
  qualifying candidates lie within min_distance of one another, it does not matter which single
  one of them is kept. Any one representative is acceptable. A region larger than min_distance 
  contributes more than one coordinate, as long as the spacing guarantee above
  is respected between all returned coordinates.
- All currently correct behavior must be preserved:
  - A strictly lower-intensity candidate within min_distance of a strictly higher one must
    remain suppressed, as it is today.
  - num_peaks, threshold_abs, threshold_rel, and exclude_border must continue to behave exactly
    as they do today.
  - The labels parameter must continue to restrict peak search to each labeled region as it
    does today, and must additionally satisfy all of the following:
    - Within each labeled region, the spacing guarantee above must hold: no two returned
      coordinates that come from the same region may be closer than min_distance apart. (Peaks
      belonging to different regions are independent of one another and need not respect
      min_distance across regions.)
    - Label values are arbitrary positive integers. They need not be consecutive and need not
      start at 1. Every region identified by a distinct positive label value must be searched
      correctly regardless of the specific integer values used. Zero remains reserved for
      background.
    - The call must not modify the caller's input arrays. In particular, the `labels` array
      passed by the caller must be left unchanged after the call returns.
  - The function must continue to work correctly for images of any dimensionality it currently
    supports, not only 2D.
- The public function signature (parameter names, order, and defaults) must not change.
