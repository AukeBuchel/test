=== Background ===
Scikit-image is a high-performance image processing project, part of the larger scikit project.
This particular module is implemented in pure python. You are going to implement a fix to
the skimage.feature.peak_local_max function. The min_distance parameter is meant to guarantee
that two peaks returned from a single call are always at least min_distance pixels apart.
This achieved using the same square neighborhood method already used by the function to
decide what counts as a "local" peak. 

In other words, no two peaks returned by the function peak_local_max may differ less than
min_distance pixels in any single axis (the max absolute difference across axes, not the Euclidian distance)

=== The problem ===
This guarantee currently holds when peaks have strictly different intensities: a smaller nearby peak
is correctly suppressed by the more intense nearby peak. However, it does not hold when two or
more candidate peaks are tied at the same (locally maximal) intensity, within min_distance from each other.
In such cases, all equal-intensity peaks are returned, regardless of how close together they are.

The described failure can be reproduced by running the following script:

```
import numpy as np
from skimage.feature import peak_local_max

image = np.zeros((30, 60))
image[15, 20:41] = 5.0  # 21 pixels, all tied at the image's max value

coords = peak_local_max(image, min_distance=10)
print(len(coords))  # currently 21 — one "peak" per plateau pixel, some 1 pixel apart
``` 
For contrast, `image[15, 30] = 5.0; image[15, 32] = 3.0` with the same `min_distance=10` already correctly returns only `[15, 30]` today — the bug is specific to ties, not distance-checking in general.
```

=== Your task ===
Fix peak_local_max so that no two coordinates it returns are ever closer than `min_distance` apart (by the metric above), including when the tied maximal value is shared by more than one candidate location. When several candidates are tied within `min_distance` of each other, it does not matter which single one of them is kept — any one representative is acceptable — but that cluster must still contribute exactly one peak to the result; it must not be dropped entirely.

The fix must preserve all currently correct behavior:
- A strictly lower-intensity candidate within `min_distance` of a strictly higher one must remain suppressed, as it is today.
- `num_peaks`, `threshold_abs`, `threshold_rel`, and `exclude_border` must continue to behave exactly as they do today.
- The `labels` parameter must continue to restrict peak search to each labeled region as it does today.
- The function must continue to work correctly for images of any dimensionality it currently supports, not only 2D.
- The public function signature (parameter names, order, and defaults) must not change.

Testing policy:
- See above for how to run the tests defined for the subject function, as well as all tests in the project.
- It is ok for not all tests to pass after you are done. You are, after all, modifying behavior from the currently tested behavior suite.
